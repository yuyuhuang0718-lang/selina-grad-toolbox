THE PROBLEM

一個看似完整的引用，可能不可信

以下為刻意造假的教學資料，不是真實論文 DOI

「Gao et al. (2023) 提出 ALCE，
DOI：10.9999/fictional-alce」

題名、作者可能正確，DOI 卻可能被編造。
更進一步，即使 DOI 存在，也必須核對文獻是否真正支持那句話。

KARPATHY LLM WIKI

跟單純上傳 PDF 問 AI，有何不同？

①

Raw sources

保留不可任意改動的官方來源筆記。

②

Linked Wiki

論文頁、概念頁、索引與交叉引用。

③

Reusable answers

查詢 Wiki 後產生可檢查的教學成果。

重點：知識會累積。 每次加入新來源都能更新舊的概念頁，也能標示來源之間的衝突。
CHECK 01 · METADATA

先確認「這篇論文真的存在」

核對 5 個欄位

  • Title：完整題名
  • Authors：作者順序
  • Year：正式出版年份
  • Venue：會議／期刊
  • DOI 或 arXiv ID

查詢順序

① 出版社／會議官方頁
② Crossref 的 metadata
③ arXiv 預印本紀錄

注意：沒有出版社 DOI，不代表論文不存在；arXiv 年份也可能不同於正式發表年份。
CHECK 02 · EVIDENCE

第二步：引用要能支持那句話

AI 生成的主張（示例）

「ALCE 用來評估引文品質。」

可找到的證據： Gao et al.（2023）Abstract 說明 ALCE 評估 fluency、correctness、citation quality。

不只找到論文，還要記下 Source ID + Section + Claim + Status。

CHECK 03 · ATOMIC FACTS

一句話其實可以包含很多事實

假設 AI 寫：「Min 等人在 2023 年於 EMNLP 提出 FActScore，用來檢查長篇生成內容的事實精確度。」

Claim A

作者與年份

Min et al.、2023

Claim B

發表場域

EMNLP 2023

Claim C

方法用途

Atomic facts factual precision

逐筆標為 Supported / Unsupported / Pending；沒有查到，不要硬寫成已證實。

INTERACTIVE CHECKPOINT · 01

選出 ALCE 的正式 DOI

請根據 Wiki 的 P02 論文頁，判斷哪個 DOI 與正式出版紀錄一致。

請選一個答案，看看 Metadata Gate 如何判定。
INTERACTIVE CHECKPOINT · 02

這個 AI 主張可以直接引用嗎？

AI 生成文字｜教學假設

「ALCE 的所有測試都達到 99% 引文正確率。」

先判斷：你真的看到原文支持這個百分比了嗎？
GRAPH & FEEDBACK LOOP

不是單向生成；錯誤要回到上游

CoVe 提供獨立查核問題的啟發；Self-RAG 提供按需檢索／反思的啟發。本作業並未聲稱訓練兩者模型。

ACTUAL GATE & LINT

把檢查往前移，減少返工

原始設想

Ingest → Query → 產生簡報 → 最後人工查資料

問題：錯誤 DOI 可能已出現在 Wiki 與 HTML。

改版設計

來源 → Metadata Gate → Wiki → Claim Lint → HTML → UI Test

好處：書目錯誤在寫 Wiki 前先攔截。

每次 Lint 失敗依類型退回：書目 → 來源；主張缺證據 → Wiki；按鈕失靈 → HTML。
